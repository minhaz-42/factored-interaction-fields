# Factored Interaction Fields

Code, configurations and analysis for **"Factored Interaction Fields: Learning Joint-Anchored
Hand-Object Proximity Through Its Geometric Arguments"**, submitted to *Image and Vision Computing*.
Preprint: <https://doi.org/10.2139/ssrn.7466725>.

The SHOW3D interaction field assigns to each of the 21 joints of a hand the 3-D vector to the
nearest point of the manipulated object. Published solutions regress those 126 numbers directly.
This work instead predicts the three quantities the field is a deterministic function of, the hand
joints, the 6-DoF object pose and a known mesh, and applies that function through a differentiable
soft nearest-vertex operator, fusing the result with a direct regression head by predicted precision.

## Result

Held-out subjects, mean average distance error in mm (lower is better). Every token-based model
shares one frozen DINOv3 ViT-B/16 cache, one decoder, one optimiser and one schedule, so the
differences are attributable to the factorisation alone.

| Model | Fold A | Fold B |
|---|---|---|
| InterField ResNet-50 (official baseline) | 60.47 | -- |
| Direct regression, stereo + Plücker rays | 46.15 / 45.73 | 35.68 |
| **Factored (ours)** | **44.43 / 43.82** | **34.08** |

Two seeds are shown where available; they are a range, not a variance estimate.

**What the analysis found, stated as the paper states it.** The improvement is carried by the
direct head, whose representation is shaped by the geometric supervision. Inference-time fusion
contributes about 0.1 mm, and the geometric head's predicted scale saturated at its clamp in four
of the five precision-fusion runs. The advantage does not transfer to HOT3D in any of four
cross-dataset settings. The geometric branch is therefore best understood as a structured auxiliary
task that can be dropped at deployment, not as a better estimator.

## Layout

```
fif/            model, geometry, metrics, training and evaluation
scripts/        label building, feature caching, experiment drivers, every figure and table
configs/        one file per run; the run name in the paper is the config name
experiments/    per-run metrics_val.json, summary.json, config.yaml, history.json
tables/         aggregated results consumed by the table generator
logs/           the logs of the runs that produced the reported numbers
paper/          LaTeX source, generated tables, the architecture figure and the built PDF
figures/        every figure in the paper, regenerated by scripts/fig_*.py
docs/           protocol, split definitions and the research log
```

## Not in this repository

| Artefact | Size | Where |
|---|---|---|
| SHOW3D and HOT3D raw data | ~100 GB | from their authors, see below |
| DINOv3 feature cache | 22 GB | regenerate with `scripts/cache_features.py` |
| Derived interaction-field labels | 774 MB | archived separately |
| Trained checkpoints, 36 files | 2.0 GB | archived separately |
| Per-frame predictions | 299 MB | archived separately |

Obtain SHOW3D through the official dataset API and HOT3D from its authors, place them under
`data/`, then run the label build and the feature cache. `fif/paths.py` resolves everything
relative to the project root, so no path editing is needed.

## Reproducing

```bash
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
python scripts/build_labels.py          # derived interaction-field labels
python scripts/cache_features.py        # frozen DINOv3 tokens, PCA to 256 dims
bash   scripts/run_all.sh               # every experiment in the paper
python scripts/make_paper_tables.py     # regenerates paper/tab/*.tex from the run artefacts
```

Every number in the paper is generated from the run artefacts by `scripts/make_paper_tables.py`
and `scripts/fig_*.py`. None is typed by hand.
